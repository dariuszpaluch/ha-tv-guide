# TV guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `tv_guide` Home Assistant integration and the `custom:tv-guide` card from the design, as one HACS-installable repository.

**Architecture:** Two tracks that meet only at the contract in `docs/api.md`. The integration downloads an XMLTV guide, keeps the selected channels, stores the last good guide and resized posters on disk, and answers WebSocket commands. The card is a Lit element that calls those commands and switches channels with an HA action from its config.

**Tech Stack:** Python 3.14, Home Assistant 2026.10.2 (schemas with `probatio` 0.13), pytest + `pytest-homeassistant-custom-component==0.13.373`, ruff, uv. TypeScript 7 (strict), Lit 3.3, Vite 8, Vitest 5 + happy-dom 21, pnpm.

**Spec:** [docs/design.md](../../design.md) and [docs/api.md](../../api.md). Visual reference: [docs/mockup/design-a.src.html](../../mockup/design-a.src.html).

## Global Constraints

- Integration domain `tv_guide`; card element `tv-guide` (`type: custom:tv-guide`); repository `dariuszpaluch/ha-tv-guide`.
- `manifest.json` `requirements` stays empty: only Python stdlib and HA core packages (aiohttp, Pillow, probatio). HA 2026.10 has no `voluptuous`: every schema uses `probatio` (`import probatio`).
- XML parsing with `xml.etree.ElementTree.iterparse` on a stream; blocking work (decompress, parse, Pillow, file I/O) runs in `hass.async_add_executor_job`.
- `docs/api.md` is the only API source. Only the coordinator changes it, in its own commit.
- TypeScript `strict: true`, no `any`; contract types live in `frontend/src/types/api.ts` and nowhere else.
- Card: only HA theme variables; every visible string through `t()` with keys in `en.ts` and `pl.ts`; posters `loading="lazy"`; times 24-hour with locale `en-GB` or `pl-PL`.
- All digits work on the author's remote, including 7. `unavailable_digits` is a generic option with default `[]`; no code or test assumes a missing digit.
- TV day starts at `tv_day_starts_at` (default 5); the server knows nothing about TV days.
- Search: programme search from 2 characters; `later` limit 40. Airings limit 20.
- Poster sizes: `thumb` 336 px wide, `large` 1200 px wide, never wider than the source, JPEG quality 80; folder `<config>/.cache/tv_guide/images/` (HA backups skip `.cache/*`, `homeassistant/components/backup/const.py`); files unused for 7 days are deleted.
- Logos shown in a 52×30 box; a logo from the card config wins over the guide icon.
- Commits: conventional, author `Dariusz Paluch <dariusz.paluch.it@gmail.com>`, no `Co-Authored-By`, never amend or squash.
- Comments and docs: plain English, short sentences, explain why.

## Review Focus

1. **DST night.** Poland leaves summer time on 2026-10-25 at 03:00. The TV day 2026-10-24 (05:00 to 05:00) is 25 hours long, and XMLTV times change from `+0200` to `+0100` inside it. Programmes keep their order, ids stay unique, the day lists every programme once. Tests: I1 `test_parse_dst_offsets`, I3 `test_schedule_dst_night`, C2 `tvDayRange spans 25 hours on 2026-10-24`.
2. **English times.** `hass.locale.language = 'en'` must still give `19:55` and `Wed 21`, not `07:55 PM` and `21 Wed`. Tests: C2 `formatTime is 24-hour in English`, `dayLabel in English`.
3. **Channel without guide data** (`epg_id` missing or not in the guide). The row shows "No guide", the details show "No programme guide for this channel.", search and airings skip it, no errors. Tests: I3 `test_now_unknown_channel`, `test_schedule_unknown_channel`, C6 `channel row without programme shows No guide`, C8 `channel view without programmes`.
4. **First start with the source down and no stored guide.** HA retries the setup, the WebSocket answers `not_loaded`, the card shows "The guide is not loaded yet." instead of an empty list. Tests: I4 `test_setup_retries_when_source_down`, I5 `test_not_loaded_while_setup_retry`, C9 `shows not loaded message`.
5. **Search text.** `życie`, `zycie` and `ŻYCIE` all find "Życie na fali"; `(` and `*` are plain characters; a 1-character query never reaches the server. Tests: I3 `test_search_ignores_case_and_diacritics`, `test_search_special_characters`, C4 `does not call the server below 2 characters`.
6. **Memory during an update.** The decompressed XML (about 100 MB for epg.ovh) must never be in memory as one object. Test: I2 `test_open_source_streams` and the I1 parser taking a stream.
